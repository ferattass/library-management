## 1. Primary Key Yapıları

Tüm ana varlıklarda **tek kolonlu, `INT GENERATED BY DEFAULT AS IDENTITY`** surrogate key kullanılır.

| Tablo | Primary Key | Tip |
|---|---|---|
| `users` | `id` | Surrogate |
| `roles` | `id` | Surrogate |
| `authors` | `id` | Surrogate |
| `categories` | `id` | Surrogate |
| `publishers` | `id` | Surrogate |
| `books` | `id` | Surrogate |
| `borrowings` | `id` | Surrogate |
| `reservations` | `id` | Surrogate |
| `reviews` | `id` | Surrogate |
| `user_roles` | `(user_id, role_id)` | **Composite** |
| `book_authors` | `(book_id, author_id)` | **Composite** |
| `book_categories` | `(book_id, category_id)` | **Composite** |

**Neden UUID değil?** Kayıtlar dışarıya sızdırılan/tahmin edilmemesi gereken kimlikler değil, ve `INT` hem index boyutu hem join maliyeti açısından belirgin biçimde daha ucuz. Çok kiracılı veya dağıtık ID üretimi gerekseydi UUIDv7 tercih edilirdi.

**Neden ara tablolarda composite PK?** `(book_id, author_id)` çiftinin kendisi doğal ve benzersizdir. Ayrı bir `id` eklemek, ek bir unique index gerektirir ve hiçbir sorguda kullanılmaz — gereksiz yazma maliyeti.

## 3. Composite Key Kullanılan Tablolar

Üç saf birleştirme (junction) tablosu:

```sql
user_roles      PRIMARY KEY (user_id, role_id)
book_authors    PRIMARY KEY (book_id, author_id)
book_categories PRIMARY KEY (book_id, category_id)
```

Bu PK'lar aynı zamanda ilk kolon üzerinde otomatik index sağlar. **İkinci kolon için ayrıca index gerekir** — aksi halde "bu yazarın tüm kitapları" gibi ters yönlü sorgular tam tarama yapar. Bkz. Bölüm 5.

## 4. Unique Alanlar

| Tablo | Kısıt | Kapsam |
|---|---|---|
| `users` | `UNIQUE (email)` | Tam tablo — BR-01.1 |
| `roles` | `UNIQUE (name)` | Tam tablo |
| `categories` | `UNIQUE (name)`, `UNIQUE (slug)` | Tam tablo |
| `publishers` | `UNIQUE (name)` | Tam tablo |
| `books` | `UNIQUE (isbn)` | `NULL` hariç — BR-02.1 |
| `reviews` | `UNIQUE (user_id, book_id)` | Tam tablo — **BR-05.2** |
| `reservations` | `UNIQUE (user_id, book_id) WHERE status IN ('PENDING','READY')` | **Kısmi** — BR-04.1 |

### E-posta benzersizliği ve harf duyarlılığı

`users.email` için `CITEXT` uzantısı kullanılır. `VARCHAR` ile `Ali@x.com` ve `ali@x.com` iki ayrı kayıt olabilirdi — bu hem BR-01.1'i deler hem de giriş sırasında kafa karıştırıcı davranış üretir.

```sql
CREATE EXTENSION IF NOT EXISTS citext;
```

### ISBN ve NULL davranışı

PostgreSQL'de `UNIQUE`, birden fazla `NULL`'a izin verir. ISBN'i olmayan kitaplar (eski basımlar, yerel yayınlar) sorunsuz eklenebilir; ISBN girildiğinde ise benzersizlik zorlanır. İstenen davranış tam olarak budur.

### Rezervasyonda neden kısmi index?

Basit `UNIQUE (user_id, book_id)` kullanılsaydı, kullanıcı bir kitabı rezerve edip iptal ettikten **sonra bir daha asla** rezerve edemezdi. Kural yalnızca *aktif* rezervasyonlar için geçerli olduğundan (BR-04.1), index de yalnızca aktif satırları kapsamalıdır:

```sql
CREATE UNIQUE INDEX reservations_active_user_book_uniq
  ON reservations (user_id, book_id)
  WHERE status IN ('PENDING', 'READY');
```

> Prisma şema DSL'i kısmi unique index'i ifade edemez; bu yüzden migration SQL'ine elle eklenmiştir.

## 5. Index Gerektiren Alanlar

### 5.1 Foreign key kolonları

PostgreSQL, FK kolonlarına **otomatik index oluşturmaz**. Indexlenmeyen FK, hem join'leri hem de ebeveyn tablodaki `DELETE`/`UPDATE` işlemlerini yavaşlatır.

```sql
CREATE INDEX ON books           (publisher_id);
CREATE INDEX ON borrowings      (user_id);
CREATE INDEX ON borrowings      (book_id);
CREATE INDEX ON reservations    (user_id);
CREATE INDEX ON reservations    (book_id);
CREATE INDEX ON reviews         (book_id);
CREATE INDEX ON user_roles      (role_id);        -- ters yön
CREATE INDEX ON book_authors    (author_id);      -- ters yön
CREATE INDEX ON book_categories (category_id);    -- ters yön
```

`reviews(user_id)` ayrıca gerekmez — `UNIQUE (user_id, book_id)` index'i `user_id` ile başladığı için o yönü zaten karşılar.

### 5.2 Sprint 4 sorgu desenleri

| Sorgu | Index |
|---|---|
| `?sortBy=title` + sayfalama | `CREATE INDEX ON books (title);` |
| `?sortBy=publishedYear` | `CREATE INDEX ON books (published_year DESC NULLS LAST);` |
| `?search=harry` | GIN trigram — aşağıya bakınız |

### 5.3 Arama index'i (`?search=`)

Arama `ILIKE '%harry%'` şeklinde çalışacaktır. Baştaki joker karakter yüzünden B-tree index **kullanılamaz**. Çözüm `pg_trgm` + GIN:

```sql
CREATE EXTENSION IF NOT EXISTS pg_trgm;

CREATE INDEX books_title_trgm_idx    ON books   USING GIN (title gin_trgm_ops);
CREATE INDEX authors_name_trgm_idx   ON authors USING GIN ((first_name || ' ' || last_name) gin_trgm_ops);
```

Bu, `%harry%` gibi ortadan eşleşen aramaları da index'ten karşılar. Tam metin arama (`tsvector`) alternatifi kelime köküne göre çalışır ve kısmi kelime eşleşmesini kaçırır — kitap başlığı araması için trigram daha uygundur.

### 5.4 Kısmi (partial) index'ler

Aktif kayıtlar toplam satırların küçük bir yüzdesidir; sorgular neredeyse her zaman yalnızca onlara bakar:

```sql
-- BR-03.4 / BR-03.5: kullanıcının aktif ödünçleri
CREATE INDEX borrowings_active_idx ON borrowings (user_id, book_id)
  WHERE status IN ('BORROWED', 'LATE');

-- BR-04.2: kitabın rezervasyon kuyruğu, sıralı
CREATE INDEX reservations_queue_idx ON reservations (book_id, queue_position)
  WHERE status = 'PENDING';

-- BR-03.1: stokta olan kitaplar
CREATE INDEX books_available_idx ON books (id) WHERE available_copies > 0;
```

| Amaç | Adet |
|---|---|
| Primary key (otomatik) | 12 |
| Unique kısıt (otomatik) | 7 |
| Foreign key desteği | 9 |
| Sıralama (Sprint 4) | 2 |
| Trigram arama (Sprint 4) | 2 |

## 6. CHECK Kısıtları

İş kurallarının **veritabanı seviyesinde** garanti edilen kısmı. Uygulama katmanındaki bir hata bu kısıtları aşamaz.

```sql
-- BR-03.2: stok asla negatif olamaz  <-- şartnamenin en kritik maddesi
ALTER TABLE books ADD CONSTRAINT books_available_copies_non_negative
  CHECK (available_copies >= 0);

-- BR-02.6
ALTER TABLE books ADD CONSTRAINT books_total_copies_non_negative
  CHECK (total_copies >= 0);
ALTER TABLE books ADD CONSTRAINT books_available_lte_total
  CHECK (available_copies <= total_copies);

-- BR-05.1: puan 1-5
ALTER TABLE reviews ADD CONSTRAINT reviews_rating_range
  CHECK (rating BETWEEN 1 AND 5);

-- Mantıksal tutarlılık
ALTER TABLE borrowings ADD CONSTRAINT borrowings_due_after_borrowed
  CHECK (due_date > borrowed_at);
ALTER TABLE borrowings ADD CONSTRAINT borrowings_returned_status_consistent
  CHECK ((status = 'RETURNED') = (returned_at IS NOT NULL));
```

Son kısıt, `status` ile `returned_at` alanlarının birbiriyle çelişmesini imkânsız kılar — "iade edilmiş görünen ama iade tarihi boş" gibi bir satır oluşturulamaz.

> Prisma şema DSL'i `CHECK` kısıtını ifade edemez; bunlar migration SQL'ine elle eklenmiştir.

## 7. Enum Tipleri

```sql
CREATE TYPE role_name          AS ENUM ('USER', 'ADMIN');
CREATE TYPE borrowing_status   AS ENUM ('BORROWED', 'RETURNED', 'LATE');
CREATE TYPE reservation_status AS ENUM ('PENDING', 'READY', 'FULFILLED', 'CANCELLED', 'EXPIRED');
```

Native enum, `VARCHAR + CHECK`'e göre daha az yer kaplar ve tip güvenliğini Prisma Client'a kadar taşır. Karşılığında yeni değer eklemek migration gerektirir — bu alanlar için kabul edilebilir bir takas.

## 8. Zaman Damgaları

Tüm zaman kolonları `TIMESTAMPTZ` (UTC olarak saklanır). `TIMESTAMP` (tz'siz) kullanılsaydı, sunucu saat dilimi değiştiğinde veya farklı bölgelerden erişimde `dueDate` hesapları kayardı.
